# 손동작 스티어링

웹캠 2대로 두 사람의 손을 각각 읽어 **가상 Xbox 360 패드 2개**로 흘려보낸다.
게임 쪽은 고칠 것이 없다 — 브라우저에는 그냥 실제 컨트롤러 두 대로 보인다.

의자가 고정되어 있고 카메라가 한 자리씩 전담하므로 얼굴 인식이나 앵커 추적이 필요 없다.
"이 카메라에 잡히는 손 = 이 플레이어 손". 대신 가로 화각을 좁게 잘라 옆자리나 구경꾼이
프레임에 아예 안 걸리게 한다.

## 설치

**1. ViGEmBus 드라이버** — vgamepad가 요구하는 커널 드라이버다. 이게 없으면 실행 즉시 실패한다.

<https://github.com/nefarius/ViGEmBus/releases> 에서 `ViGEmBus_x64_*.exe` 받아 설치하고 재부팅.

**2. 파이썬 패키지**

```powershell
pip install opencv-python mediapipe vgamepad
```

**3. 손 인식 모델** — 이 폴더에 `hand_landmarker.task` 로 저장한다.

```powershell
curl -o handsteer/hand_landmarker.task https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task
```

## 실행

```powershell
python handsteer/hand_steering.py --list    # 카메라 번호 확인 (처음 한 번)
python handsteer/hand_steering.py           # 실행
```

`--list`로 확인한 번호를 스크립트 상단의 `P1_CAM_INDEX` / `P2_CAM_INDEX`에 적어 둔다.

스크립트를 먼저 띄우고, 게임 창(<http://localhost:8000>)을 클릭해 포커스를 준 뒤 손을 든다.
브라우저는 패드에서 입력이 들어와야 인식하므로 손을 한 번 흔들면 연결된다.
종료는 카메라 창에서 `q`.

## 제스처

| 동작 | 입력 | 패드로는 |
|---|---|---|
| 양손을 핸들처럼 들고 기울이기 | 조향 | 좌스틱 X |
| 기본 상태 | 가속 | RT 항상 ON |
| 양손 다 주먹 | 브레이크 | LT |
| **한 손만 주먹** | 아이템 사용 | X 버튼 (누를 때 1회) |
| **양손을 가운데로 모으기** | 시작 / 확인 | A 버튼 (누를 때 1회) |
| 양손을 같이 위/아래로 | 메뉴 항목 이동 | 좌스틱 Y |

굵게 표시한 둘은 원본 스크립트에 없던 것이다. 게임의 패드 매핑이 `A/Start = 시작`,
`X 또는 LB = 아이템`이라, 이 제스처가 없으면 **손만으로는 레이스를 시작할 수도 아이템을
쓸 수도 없다**. 조향·가속·브레이크만으로는 타이틀 화면에서 멈춘다.

## 현장 조정

**`CROP_WIDTH_RATIO`** (기본 0.35) — 가운데에서 남길 가로 비율. 사람 한 명의 상반신과
양손이 딱 들어올 정도로 줄인다. 옆 사람 손이 잡히면 더 줄이고, 자기 손이 프레임 밖으로
나가면 늘린다.

**`MAX_ANGLE_DEG`** (기본 45) — 이 각도에서 조향이 최대가 된다. 줄이면 예민해진다.

**`FIST_RATIO`** (기본 0.45) — 주먹 판정 문턱. 주먹이 잘 안 잡히면 올리고, 편 손이
주먹으로 오인되면 내린다.

**`CONFIRM_RATIO`** (기본 0.55) — 손을 얼마나 모아야 확인으로 볼지. 주행 중 실수로
발동하면 내린다.

카메라를 물리적으로 90도 돌려 거치했다면 `CAMERA_IS_PHYSICALLY_ROTATED = True`로 두고
크롭 대신 회전을 쓴다.

## 원본에서 고친 것

**각도를 픽셀 공간에서 계산하도록 바꿨다.** 정규화 좌표로 `atan2(dy, dx)`를 하면 크롭
비율만큼 각도가 왜곡된다 — 가로를 35%로 자르면 x는 448px, y는 720px 기준으로 정규화되기
때문에, 실제 16.7도가 10.6도로 읽혀 **조향이 0.63배로 둔해진다**. 크롭을 좁힐수록 더 심해진다.

**주먹 판정을 손 크기 기준 상대값으로 바꿨다.** 원본은 정규화 거리를 고정 임계값(0.06)과
비교하는데, 이러면 카메라에서 멀어질수록 손이 작게 잡혀 편 손도 주먹으로 오판한다.
손목→중지 밑마디 거리를 기준자로 삼아 거리와 무관하게 만들었다.

**MediaPipe 타임스탬프를 실제 경과 시간으로 바꿨다.** 원본은 프레임당 33ms 고정을
가정하는데, 카메라 2대를 번갈아 처리하면 실제 간격이 그보다 길어 추적이 어긋난다.

그 외 `cv2.CAP_DSHOW` 지정(윈도우에서 카메라 열기가 빨라진다), 모델 파일 없을 때
안내 메시지, `--list` 카메라 확인 모드, 종료 시 패드 리셋을 `finally`로 보장.

## 알아둘 것

**RT가 항상 켜져 있다.** 손을 내려도 카트는 계속 가속한다(브레이크는 양손 주먹). 손이
프레임에서 사라지면 조향만 0이 되고 직진한다.

**패드 순서.** 먼저 만든 가상 패드가 보통 브라우저에서 0번(P1)이 된다. 좌우가 바뀌면
`P1_CAM_INDEX`와 `P2_CAM_INDEX`를 서로 바꾸는 게 제일 간단하다.

**두 카메라를 한 프로세스에서 번갈아 처리**하므로 체감 프레임레이트가 카메라 하나일 때의
절반쯤 된다. 손 추적은 30fps면 충분하지만, 버벅이면 `CAPTURE_WIDTH/HEIGHT`를 640×480으로
낮추는 게 가장 효과가 크다.
